Writing and Debugging Charts

Sooner or later a chart fails to render, and the error mentions a line number, an angle-bracketed expression and "nil pointer". This lesson opens the chart up: how templates turn values into YAML, and how to find out which of the two stages went wrong.

⏱ 50 min
🎯 Goal of this lesson

Read and write Helm templates, and debug charts with helm lint and helm template.

Why it matters: template errors happen before anything reaches the cluster, so no Kubernetes tool can help you. The fix is quick once you know that rendering has two stages and which message belongs to which.

By the end of this lesson you will be able to

  • Describe the layout of a chart.
  • Use values, built-in objects, pipelines, conditionals and loops in templates.
  • Control whitespace and indentation with {{- and nindent.
  • Tell a template error from a YAML parse error and locate each.
  • Render a chart locally to inspect its output.

The layout of a chart

web/
├── Chart.yaml            name, version, appVersion
├── values.yaml           default values
└── templates/
    ├── _helpers.tpl      named snippets ("define"), not rendered by itself
    ├── deployment.yaml   ┐
    ├── service.yaml      │ templates: YAML with {{ ... }} placeholders
    ├── ingress.yaml      ┘
    └── NOTES.txt         text shown after install
helm create hello          # scaffold a new chart
helm lint hello            # static checks, including a test render
helm template demo hello   # render locally and print the manifests; nothing is installed

Templates in five steps

1. Values and built-in objects

metadata:
  name: {{ .Release.Name }}
spec:
  replicas: {{ .Values.replicaCount }}
  template:
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
ObjectContains
.ValuesThe merged values: chart defaults, your files, --set
.Release.Name, .Namespace, .Revision, .IsInstall, .IsUpgrade
.ChartFields of Chart.yaml, capitalised: .Name, .Version, .AppVersion

2. Pipelines and functions

A value can be passed through functions with |, like a shell pipe:

ExpressionEffect
{{ .Values.name | quote }}Wraps the value in double quotes. Essential for strings that look like numbers or booleans.
{{ .Values.tag | default "latest" }}Uses the fallback when the value is empty.
{{ required "image.tag is required" .Values.image.tag }}Aborts rendering with your message when the value is missing.
{{ toYaml .Values.resources | nindent 12 }}Dumps a whole structure as YAML, starting on a new line, indented 12 spaces.
{{ include "web.labels" . | nindent 4 }}Inserts a named snippet from _helpers.tpl.

3. Conditionals and loops

{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
# ...
{{- end }}

          env:
            {{- range $key, $value := .Values.env }}
            - name: {{ $key }}
              value: {{ $value | quote }}
            {{- end }}

4. Whitespace

A template action leaves its own line behind as an empty line. A dash inside the braces removes whitespace on that side: {{- eats everything before the action up to the previous text, including the line break; -}} does the same after it. That is why control lines are written {{- if … }} and {{- end }}.

5. Indentation is your job

Helm inserts text; it knows nothing about YAML structure. Whatever a template produces must be valid YAML at the place where it lands. For multi-line blocks, nindent N is the tool: it starts a new line and indents every line by N spaces.

❌ Breaks as soon as the value has two lines 
          resources:
            {{ toYaml .Values.resources }}

Only the first line gets the 12 spaces written in the template. The second line starts at column 0.

✅ Every line indented 
          resources:
            {{- toYaml .Values.resources | nindent 12 }}

{{- removes the template's own indentation; nindent 12 adds a line break and indents all lines.

Two stages, two kinds of error

 templates + values ──(1) evaluate Go templates──► text ──(2) parse as YAML──► manifests
                        fails with "template: …"          fails with "YAML parse error on …"

Stage 1: template errors

Error: template: web/templates/service.yaml:11:23: executing "web/templates/service.yaml" at <.Values.service.ports.http>: nil pointer evaluating interface {}.http
Part of the messageMeaning
web/templates/service.yaml:11:23File, line and column in the template source.
at <.Values.service.ports.http>The expression that failed.
nil pointer evaluating interface {}.httpSomething before .http does not exist: .Values.service.ports is undefined, so it has no field http.

The fix is always the same comparison: open values.yaml and walk the path in the expression key by key. Typical causes are a typo, a renamed value, or a nested key that only exists when an optional section is filled in.

Other stage-1 messagesCause
function "foo" not definedA misspelt function name.
unexpected EOF / unexpected {{end}}An if, range or with without its end, or one end too many.
error calling include: … no template "web.lables"A misspelt name of a snippet defined in _helpers.tpl.
error calling required: …The chart author demands a value you did not set. The message says which.
A missing leaf value is not an error {{ .Values.image.tagg }} (a typo in the last key) renders as an empty string without complaint, because looking up a missing key in an existing map is allowed. The result is an image like shop/web: and a pod in InvalidImageName. Charts guard important values with required or default for this reason.

Stage 2: YAML errors

Error: YAML parse error on web/templates/deployment.yaml: error converting YAML to JSON: yaml: line 33: did not find expected '-' indicator

The templates ran, and their output is not valid YAML. Here the line number refers to the rendered text, not to the template file, so opening the template at line 33 misleads you. Look at what was produced:

helm template web ./web --debug      # prints the rendered output even when it is invalid
          env:
            - name: PORT
              value: "8080"
          - name: API_URL          # ← two spaces too far left: not part of the list above
            value: "http://api:3000"

A chart-debugging routine

  1. helm lint CHART: reports the first problem of either stage, with the file.
  2. Template error? Compare the quoted expression with values.yaml.
  3. YAML error? helm template … --debug and look at the rendered text near the line.
  4. Renders, but looks wrong? helm template NAME CHART -f my-values.yaml -s templates/deployment.yaml shows one file with your values.
  5. Before a real upgrade: helm upgrade … --dry-run renders against the cluster and shows what would be applied.

🔑 Key takeaways

  • A chart is templates plus default values. .Values, .Release and .Chart feed the templates.
  • Helm produces text; correct YAML indentation is the template's responsibility. Use nindent for blocks.
  • Stage 1, "template: file:line … at <expr>": the expression is wrong; compare it with the values.
  • Stage 2, "YAML parse error … line N": the output is broken; the line refers to the rendered text. Use helm template --debug.
  • helm lint and helm template need no cluster. Run them in CI.

Quiz

Rendering fails with at <.Values.database.host>: nil pointer evaluating interface {}.host. What is wrong?

The message names the field that could not be evaluated; the problem is its parent. Check whether database: is defined in the values.

Helm reports YAML parse error on web/templates/deployment.yaml: … line 40. The template file has 28 lines. Why?

Loops, includes and toYaml expand to many lines. Inspect the rendered text with helm template --debug.

What does {{- toYaml .Values.resources | nindent 10 }} do?

{{- trims preceding whitespace including the newline; nindent supplies a fresh newline and consistent indentation for all lines.
