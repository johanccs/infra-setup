    How this lab works

    Every topic starts with a short "What is it?" box: what it is, the problem it solves, an everyday comparison and what it is not. Then the detail follows, easy first. The detail goes all the way down to real messages, token bytes and certificate fields, but one new idea at a time, and the deepest parts sit in closed "Line by line" blocks you can open when you want them.

    Each lesson has exercises, and a tool in the page where one helps (a token decoder, a certificate reader, a sign-in flow you can attack). The tools run in your browser and send nothing anywhere. A step ticks itself only when every exercise in it is passed.

    Every fact is taken from the standard that defines it (the RFCs, the OpenID Connect specifications, NIST) or from the product's own documentation, and each lesson ends with its sources and the date they were checked. Where something could not be run and tested, the page says so.

    Words people mix up

    These are the pairs that cause the most confusion. Each is explained properly in its own lesson.

    TermWhat it isWhat it is not
    OAuth 2.0A framework that lets an app obtain limited access to a service, on someone's behalf or on its own.Not a login protocol. It says what an app may do, not who signed in.
    OpenID ConnectA simple identity layer on top of OAuth 2.0. It lets an app verify who signed in.Not a separate system: it uses OAuth 2.0's messages and adds an ID token.
    SAML 2.0An OASIS standard (15 March 2005) that carries sign-in information between organisations as XML assertions. Its main use case is web single sign-on.Not built on OAuth. It does a similar job to OpenID Connect in a different format.
    RoleA named set of permissions given to people inside a system, such as admin.Not the same as a scope.
    ScopeA named permission an app asks for when it requests a token, such as openid.Not a role: the server may grant less than was asked.
    ClaimA statement inside a token, such as who issued it or when it expires.Not a permission by itself. A role or a scope can travel as a claim.
    401The request has no valid authentication credentials. The server must say how to authenticate, in a WWW-Authenticate header.Not "you may not". That is 403.
    403The server understood the request and refuses it. Credentials, if any, are not enough.Not "who are you?". That is 401.
    404No representation was found, or the server is not willing to disclose that one exists.Not always "it does not exist": it can hide a resource from someone who may not know of it.

    Glossary

    Short definitions, in the standards' own meaning. Each term gets its "What is it?" box where it is first used.

    Authentication
    Proving who or what is making a request.
    Authorization
    Deciding what an authenticated caller may do.
    Credential
    Something used to prove an identity: a password, a key, a token, a certificate.
    Identity provider
    The service that signs users in and tells other applications who they are. OpenID Connect calls it the OpenID Provider.
    Resource owner, client, authorization server, resource server
    The four OAuth roles: the one who can grant access (often you), the app that wants access, the server that issues access tokens, and the server that holds the protected data.
    Token
    A string an app presents to show what it is allowed to do, instead of presenting a password.
    Bearer token
    A token that any party in possession of it can use, in any way another holder could. Whoever holds it can use it. It travels in a header such as Authorization: Bearer ….
    JWT
    JSON Web Token: a compact, URL-safe way to carry claims between two parties, as a JSON object that can be signed or encrypted. Its three parts are joined with dots: header.payload.signature.
    PKCE
    Proof Key for Code Exchange: a technique that protects the authorization code flow against an intercepted code.
    RBAC
    Role-based access control: permissions are granted to roles, and people are given roles.
    Single sign-on
    One sign-in that lets you use several applications.
    TLS
    Transport Layer Security: the protocol that lets two programs talk over the Internet in a way designed to prevent eavesdropping, tampering and message forgery.
    HTTPS
    HTTP carried over a TLS connection that has been secured for it. Its addresses start with https://.
    Certificate
    A signed document that ties a public key to a name. Internet certificates follow the X.509 format.
    Certificate authority
    An organisation that others trust to create and sign certificates.
